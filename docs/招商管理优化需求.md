# 园区招商管理优化需求（业务评审版）

版本：V0.1 ｜ 日期：2026-09-04 ｜ 状态：建议方案，待业务评审

本文将管理者视角转化为系统模块、业务规则和验收要求。属于需求提炼与系统落点方案，尚未修改业务页面，也不代表新增接口已上线。负责人、具体菜单配置、后台字段和审批权限待确认。

## 1. 目标与范围

业务目标：让管理者看清目标缺口、重点客户、推进障碍和落地结果；让招商人员每次拜访后都形成可执行、可检查的下一步。

核心闭环：客户建档 → 确认需求 → 拜访评级 → 制定下一步 → 到期督办／协调 → 再评估 → 签约 → 入驻。

本期优先完成经营总览、客户分级、跟进督办；房源、合同和入驻优先衔接现有能力。团队渠道分析后续完善。第一期不引入自动成交概率、复杂评分算法或单纯按拜访次数排名。

成功指标建议：有效在跟项目负责人完整率、下一步任务完整率达到 100%；跟进逾期率、阶段停滞率、签约转化率先建立基线，再确定改善目标，不能将建议值当成已确认考核指标。

## 3. 菜单与模块

建议在运营管理端设置“招商管理”，已有同名菜单时直接扩展。

| 模块 | 系统体现 | 优先级 |
|---|---|---|
| 招商工作台 | 目标完成、近期重点客户、推进异常、待我协调；指标点击进入同口径明细 | P0 |
| 招商客户 | 客户档案、招商项目列表、ABCD 与价值标签、阶段、责任人、详情记录 | P0 |
| 跟进与督办 | 拜访记录、下一步任务、逾期提醒、协调事项、周会清单 | P0 |
| 房源匹配 | 在项目详情关联候选房源，查看面积和可租状态，跳转现有资源管理 | P1，依赖房源接口 |
| 签约与入驻 | 项目关联合同、签约结果及入驻进度；汇总展示应收实收 | P1，依赖合同与财务口径 |

## 5. 客户列表与详情

列表列：客户名称、项目名称、价值标签、ABCD 等级、阶段、需求面积、预计签约日期、负责人、最近实质进展、下一步及截止时间、风险标记。

筛选：关键词、等级（含待评估）、阶段、生命周期状态、负责人、渠道、预计签约日期范围、任务逾期、阶段停滞。默认按逾期优先、等级 A/B/C/D/待评估、最近更新时间降序排列；服务端排序后分页，默认每页 20 条，可选 50／100 条。

详情包含五组信息：基本信息与需求、评级依据、跟进时间线、任务与协调、房源及合同关联。顶部固定展示等级、阶段、负责人和下一步。

主要操作：新建项目、记录拜访、调整评级、推进阶段、设置下一步、申请协调、转交负责人、暂缓／关闭／重启、关联合同。录入拜访时一并完成评级及任务，减少重复填写。

## 6. ABCD 评级及业务规则

| 等级 | 判断依据 | 默认动作建议 |
|---|---|---|
| 待评估 | 证据不足，尚不能判断 | 创建信息补齐任务 |
| A 重点推进 | 需求、预算、决策链、预计落地时间均明确，客户确认了下一项实质动作 | 建立成交推进计划，经理每周关注卡点 |
| B 积极培育 | 需求真实且园区基本匹配，仍有预算／决策人／时间等关键项未明确 | 下一步针对未明确事项补齐证据 |
| C 长期维护 | 有潜在匹配度，但需求未启动或时间较远 | 按客户需求启动时间制定维护任务 |
| D 低优先级 | 明确不匹配、拒绝或暂时没有继续投入的依据 | 选择暂缓或关闭并记录原因；可重启项目设置复查日期 |

客户价值单独标记为重点／普通／谨慎／待评估，依据产业匹配、经营稳定性和园区贡献，由人工判断并说明；不与推进等级直接相加打分。

| 编号 | 规则 |
|---|---|
| BR-001 | 新项目默认待评估，必须指定负责人；信息不足不自动判 D |
| BR-002 | 每次完成拜访都要确认评级，可保持原级，但须记录本次事实、卡点或“无卡点”，以及下一步 |
| BR-003 | 评 A 时要求填写已确认的需求、预算口径、决策链、预计签约日期与客户确认的下一步；缺项时提示补齐，禁止提交 A |
| BR-004 | 评级、阶段、生命周期分别存储。D 不自动删除或关闭；签约也不自动修改历史评级 |
| BR-005 | 每个在跟项目必须存在至少一个未完成的下一步任务。完成最后一项任务时，必须同时新建下一步或结束当前在跟状态 |
| BR-006 | 任务必须有动作、负责人、截止时间；只有“继续跟进”且无具体动作的内容由经理复核，不靠关键词自动证明有效 |
| BR-007 | 升降级保存前后值、依据、操作者、操作时间；经理可调整授权范围内项目评级，必须说明原因 |
| BR-008 | 跟进逾期不自动降级；经理查看证据后人工判断。评级不是惩罚工具 |
| BR-009 | 暂缓必须有原因和复查日期；关闭必须有流失原因，终止未完成任务。历史记录保留，重启需写明新依据和新任务 |
| BR-010 | 同企业同需求先提示重复项目；租赁申请重复转入必须返回原项目，不能重复创建 |
| BR-011 | 拜访、评级变化、关联任务在后端同一事务保存；失败全部回滚，用户输入保留 |
| BR-012 | 变更负责人同步提示未完成任务及协调事项；用户明确选择接续负责人，交接结果留痕 |

跟进期限建议可配置：A 默认 3 天、B 7 天、C 30 天，作为新建任务时的建议值，允许根据客户约定修改。阶段停滞建议默认 14 天无阶段变化，标注“需关注”，经理可登记合理等待原因和复查日期；以上天数均待业务确认。

## 7. 状态与督办流程

招商阶段：初步接触 → 需求确认 → 实地看园 → 方案报价 → 商务谈判 → 合同签署 → 入驻交付。前五阶段允许注明原因后跳过或回退；合同签署与入驻交付必须由关联业务记录验证，不能靠拖动状态计入业绩。

| 对象 | 状态变化 | 条件及处理 |
|---|---|---|
| 项目生命周期 | 在跟 → 暂缓／关闭 | 原因必填；暂缓须复查日期，未完成任务取消并留痕 |
| 项目生命周期 | 暂缓／关闭 → 在跟 | 新依据、负责人、评级确认和下一步必填 |
| 项目生命周期 | 在跟 → 已成交 | 关联合同达到经确认的有效签约状态；后续进入履约跟踪 |
| 已成交项目 | 合同撤销／终止 | 保留历史签约事实，单列撤销影响；经理确认重启或关闭，不能直接删除历史 |
| 跟进任务 | 待完成 → 已完成／已取消 | 完成须结果，取消须原因；逾期是计算标记，不是互斥状态 |
| 协调事项 | 待处理 → 处理中 → 待确认 → 已解决 | 处理人提交结果，项目负责人确认；不通过回到处理中 |
| 协调事项 | 未解决状态 → 已取消 | 发起人或授权经理填写原因；保存历史 |

督办只创建系统内提醒和待办。截止时间已过且未完成即为逾期；同一事项同一提醒周期去重，完成后撤销未读待办。提醒接收人是任务负责人，逾期升级给其授权经理；升级时间待确认，建议次日。修改期限保留原期限与原因，不能通过改日期抹除历史逾期事实。

周会清单按当前授权与筛选生成：本周新增 A／B、阶段前进、逾期、停滞、需协调、预计下周签约，逐项查看负责人和动作。

## 8. 核心字段与数据口径

以下为新增核心字段建议，实际名称应映射现有企业和项目主键；完整接口字段在确认后台模型后补齐。

| 对象／字段 | 类型与范围 | 必填／默认／校验 |
|---|---|---|
| 客户 customerId、customerName | string；ID 按现有规范，名称 1—200 字 | 必填；优先关联企业主数据，名称不能作为唯一身份 |
| 项目 projectId、parkId、ownerId | string | ID 服务端生成；园区与负责人必填并校验数据权限 |
| 项目 projectName | string，1—200 字 | 必填，无默认 |
| 项目 grade | enum：UNRATED/A/B/C/D | 必填，默认 UNRATED |
| 项目 valueLevel | enum：UNRATED/KEY/NORMAL/CAUTIOUS | 必填，默认 UNRATED |
| 项目 stage | enum：CONTACT/NEEDS/VISIT/PROPOSAL/NEGOTIATION/CONTRACT/OCCUPANCY | 必填，默认 CONTACT |
| 项目 lifecycle | enum：ACTIVE/PAUSED/CLOSED/WON | 必填，默认 ACTIVE |
| 项目 demandAreaMin、demandAreaMax | decimal，㎡，2 位小数，正数 | 可空；同时有值时 min≤max；A 至少确认一个明确范围或精确面积 |
| 项目 budgetDescription | string，1—500 字 | 可空；A 必填，须说明币种、单价／总价及计费周期 |
| 项目 decisionChain | string，1—1000 字 | 可空；A 必填，记录角色及确认依据 |
| 项目 expectedSignDate | date，YYYY-MM-DD | 可空；A 必填；历史延期不强制改成未来日期，进入异常清单 |
| 项目 channelId | string | 可空，显示“未记录”，不虚构渠道 |
| 评级 gradeReason | string，1—1000 字 | 每次评级确认必填，无默认 |
| 跟进 visitAt、facts、blocker | datetime；文本各最多 2000 字 | 时间与事实必填；blocker 可空，界面主动选择“无卡点”可提交空值 |
| 跟进 previousGrade、newGrade | grade 枚举 | 服务端读取原等级，新等级由本次确认输入 |
| 任务 action、assigneeId、dueAt | 文本 1—500 字、string、datetime | 在跟项目必填；新任务截止时间须晚于提交时间 |
| 任务 result、cancelReason | string，各 1—1000 字 | 完成／取消时对应必填 |
| 协调 issue、supportNeeded、assigneeId、dueAt | 文本各 1—1000 字、string、datetime | 发起时均必填；未配置审批权的人员只能协调，不能批准报价 |
| 关联 contractIds、resourceIds | string[] | 默认 []；按项目园区及权限校验，可多选；合同金额与面积不复制为可编辑权威值 |
| 审计 version、createdAt、updatedAt | 正整数、datetime、datetime | 服务端生成；更新携带 version 防止覆盖他人修改 |

所有 datetime 交换为带时区 ISO 8601，显示按 Asia/Shanghai；统计周期采用左闭右开。金额采用人民币元、2 位小数，展示万元时标单位；月租、年租、应收、实收分开，不直接相加。

新增可空字段用 null 表示未知，不用 0 代替未知面积或金额；文本去掉首尾空格后空串视为缺失。更新请求字段缺失表示不修改，null 仅可清空允许空值的字段；数组 [] 表示显式清空关联，必须有权限。历史客户迁移为待评估，缺责任人或任务进入补齐清单，不伪造历史评级。

| 指标 | 口径 |
|---|---|
| 本期签约面积 | 按签约时间、当前筛选园区汇总有效租赁合同面积；同合同只计一次，关联多个项目不重复计数；退签影响单列 |
| 目标缺口 | max（本期签约目标－本期签约面积，0）；无目标不计算完成率，目标为 0 时完成率显示“—” |
| 本期入驻面积 | 按实际交付／入驻时间汇总经确认的去重房源面积，与签约面积分列 |
| A／B 数量 | 当前在跟项目数量；企业数另按 customerId 去重并明确单位 |
| 预计本期签约 | 在跟项目 expectedSignDate 落在本期的项目清单及需求面积范围；不是承诺收入，不乘拍脑袋概率 |
| 出租率 | 同一时点已出租可租面积／全部可出租面积；分母为 0 时显示“—”；房源口径未核实前不上线该指标 |
| 转化率（后续） | 按同一批进入阶段的项目追踪转出结果；说明观察期和未结束项目，不用当月签约数随意除以当月新增数 |

## 9. 权限与异常

| 角色 | 数据范围与操作 |
|---|---|
| 园区管理者 | 授权园区汇总、客户项目、分配、督办、评级调整；跨园区需要明确授权 |
| 招商经理 | 授权团队项目及任务、交接、复核、协调确认 |
| 招商人员 | 本人负责及被授权协作项目的拜访、任务、评级和协调发起 |
| 协调处理人 | 被分派事项及必要上下文、反馈；不因此获得全部客户商务数据 |

权限标识、组织层级映射待接入现有体系；服务端校验园区、归属、角色和对象权限。企业端不可读取内部评级、预算和协调记录；导出遵循相同范围，不默认开放批量导出。

加载显示占位，空列表显示创建或调整筛选入口；校验错误定位字段；保存失败保留输入；403 提示无权限；409 提示数据已更新并允许刷新后重填，禁止静默覆盖；跨业务关联接口失败显示未同步，不视作签约或入驻成功。

## 10. 接口能力清单与研发落点

本节定义接口职责，路径、现有响应包络和实际字段待与后端确认，不能把建议接口声明视为后端已可用。

| 能力 | 请求内容 | 返回内容／关键约束 |
|---|---|---|
| 工作台查询 | 园区、周期、团队／负责人 | 目标与实际、重点项目、异常计数、同步时间；服务端按完整授权数据聚合 |
| 项目分页／详情 | 筛选、排序、pageNo、pageSize／projectId | list、total／项目字段、跟进、任务、协调、关联；总数不得由当前页推算 |
| 项目新增／更新 | 项目字段、version、请求唯一标识 | 项目 ID 与新版本；校验重复、权限和版本 |
| 提交拜访与评级 | projectId、version、拜访事实、等级依据、下一步任务 | 跟进 ID、评级历史、任务 ID、新版本；同一事务，重复请求不重复写入 |
| 任务／协调流转 | 对象 ID、version、目标状态、结果或原因 | 最新状态及版本；禁止非法跳转 |
| 项目暂缓／关闭／重启 | projectId、version、原因、复查日期或新任务 | 最新生命周期及任务处理结果；事务一致 |
| 租赁申请转项目 | applicationId、目标客户、负责人、园区 | projectId；同一申请转入幂等，读取权限与写入权限均验证 |
| 合同／房源／入驻关联 | projectId、version、关联对象 ID | 经授权校验后的关联及权威状态；需核实已有查询能力 |
| 目标与规则设置 | 园区、周期、目标面积／跟进和停滞规则 | 保存版本、变更记录；仅授权管理者可写 |

建议错误分类：INVALID_ARGUMENT（字段校验）、FORBIDDEN（无权限）、NOT_FOUND（不存在）、VERSION_CONFLICT（版本冲突）、INVALID_TRANSITION（非法状态）、DUPLICATE_SOURCE（重复转入）、DEPENDENCY_UNAVAILABLE（依赖不可用）。具体业务码映射项目已有规范。重复转入返回原项目，已处理写请求返回原结果；超时重试复用同一请求唯一标识。

建议新增业务实现目录 `src/features/investment-management/`，分别承载工作台、客户项目、跟进督办具名页面；运营端在 `src/views/ToOManage/` 增加薄入口；API 集中声明于 `src/service/api/modules/`。首页只聚合招商摘要。后端菜单权限与页面路由一起交付，不能仅新增 Vue 文件后视为用户可访问。

## 11. 第一阶段验收

| 编号 | Given / When / Then |
|---|---|
| AC-01 | 给定授权招商人员，新建客户项目时指定负责人并创建任务，保存后列表和详情一致显示待评估、当前阶段与下一步 |
| AC-02 | 给定 B 项目，提交 A 评级但缺预算／决策链／日期／动作依据时，前后端均拒绝并指出缺项；补齐后评级历史、拜访及任务同时保存 |
| AC-03 | 给定 ACTIVE 项目只有一项未完成任务，完成任务时未补下一步也未结束在跟状态，系统阻止提交 |
| AC-04 | 给定未完成任务超过截止时间，工作台可进入对应明细；完成后从当前逾期清单移除，历史逾期事实保留 |
| AC-05 | 给定同一保存请求重复发送，只有一条拜访与一组任务；模拟事务失败时无部分评级或任务残留 |
| AC-06 | 给定两人打开同版本项目，先后修改时后提交者收到版本冲突，不能覆盖先提交者 |
| AC-07 | 给定 D 项目，评级后仍保留记录；选择暂缓要求原因和复查日期；重启要求依据和下一步 |

| AC-09 | 给定目标缺失、空列表或接口失败，分别显示未设置、空态、失败重试，不能统一显示 0 或演示数 |

| AC-12 | 给定历史数据缺评级或下一步，上线后标为待评估／待补齐，不自动补成 A 或伪造跟进时间 |

房源与签约联动阶段追加：同一申请重复转入得到同一项目；同合同关联多个项目时签约面积只计一次；无有效合同不能人工推进为签约；仅签约未交付的项目不计入已入驻面积。

## 12. 分期与待确认

第一阶段：核对既有招商菜单／低代码模型，确定企业与项目主键；完成评级、拜访任务事务、权限、工作台统计和目标设置；迁移历史记录为待评估，接入正式接口并验收。

第二阶段：房源匹配、申请转项目、合同关联及入驻同步，核实合同状态与金额／面积口径后展示经营结果。

第三阶段：团队渠道分析、租金回款联动、按真实业务数据优化规则。

上线依赖：后端持久化、汇总统计、提醒调度、菜单权限以及联动查询接口。前端本地存储不能作为多人协作的正式交付。回退通过关闭新菜单／入口并保留已写业务和审计数据完成，不删除客户数据。

| 待确认事项 | 推荐方案 | 对实施的影响 |
|---|---|---|
| 已有招商功能在哪里维护 | 先查动态菜单、低代码表单与后端模型 | 决定扩展旧表或新增项目模型 |
| 招商以租赁为主还是含出售／合作 | 第一版按租赁招商设计，其他类型后续单列 | 决定需求、金额及成交口径 |
| ABCD 判定与跟进期限 | 采用本文初始标准，天数后台可配置 | 决定表单校验与提醒 |
| 管理角色及园区权限 | 沿用现有组织与授权范围 | 决定可见范围、负责人及协调操作 |
| 签约与入驻权威状态 | 以合同、企业及交付系统记录核实 | 决定经营指标是否可正式展示 |
| 房源可租面积和渠道成本来源 | 无权威数据时展示未接入，不推算 | 决定第二、三阶段范围 |
