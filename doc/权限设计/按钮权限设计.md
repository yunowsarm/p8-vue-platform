# 按钮权限设计与前端使用说明

## 1. 目标与范围

本方案用于控制菜单页面内的按钮、操作入口等前端展示权限。

- 菜单/页面权限由 `/menu/list` 返回的菜单资源控制。
- 按钮权限由 `/button/list` 返回的按钮资源控制。
- 前端负责隐藏无权限入口；新增、编辑、删除、导出等业务接口仍必须由后端校验同一权限，前端控制不能替代服务端鉴权。

## 2. 按钮资源设计

在系统资源管理中，为每个业务操作建立一条 `BUTTON` 类型资源，并授予相应角色。

推荐命名规则：`页面标识_操作标识`，全部使用英文、数字和下划线。例如：

| 页面 | 操作 | 权限码（`name`） | 展示名（`title`） |
| --- | --- | --- | --- |
| 智能梯控 | 新增电梯 | `elevatorControl_add` | `新增电梯` |
| 智能梯控 | 编辑电梯 | `elevatorControl_edit` | `编辑电梯` |
| 智能梯控 | 删除电梯 | `elevatorControl_delete` | `删除电梯` |

接口返回字段的约定：

| 字段 | 用途 |
| --- | --- |
| `name` | 唯一的权限码；前端和后端均使用它鉴权。 |
| `title` | 页面显示的按钮文案，不作为权限判断条件。 |
| `id` | 按钮资源 ID；标准 P8 组件内部关联和传参时可使用。 |
| `enable` | 是否启用；值为 `"0"` 时前端不展示。 |
| `isAccredit` | 当前用户是否被授予该资源；值为 `0` 或 `"0"` 时前端不展示。 |
| `location` | 标准列表组件的显示区域，如 `head`（表头）或 `row`（行操作）。自定义页面可按自身布局决定位置。 |
| `controlRule` | 标准 P8 列表组件的业务状态控制规则，例如根据记录状态置灰或隐藏。 |

示例：

```json
{
  "name": "elevatorControl_add",
  "title": "新增电梯",
  "type": "BUTTON",
  "enable": "1",
  "isAccredit": 1,
  "location": "row"
}
```

## 3. 按钮权限接口

接口：`POST /button/list`

项目中通过下面的 API 调用：

```js
this.$api['button.info']({
  resourceName: this.$route.name,
  parentUuid: '',
  permissionVo: {
    router: this.$route.name,
    resourceId: ''
  }
})
```

参数说明：

- `resourceName`：当前菜单/路由资源名。优先使用 `this.$route.name`；动态页面没有路由名时可回退至组件名 `this.$options.name`。
- `parentUuid`：父按钮资源 ID；没有层级按钮时传空字符串。
- `permissionVo.router`：当前路由资源名。
- `permissionVo.resourceId`：当前动作资源 ID；首次获取页面按钮列表时传空字符串。

接口返回的是当前用户在当前资源下被授予的按钮列表。前端应只信任同时满足以下条件的按钮：

```js
button.enable !== '0' && button.isAccredit !== 0 && button.isAccredit !== '0'
```

## 4. 推荐用法：自定义页面直接调用

自定义页面需要明确请求按钮权限时，推荐在 `created` 中加载权限并使用布尔值控制按钮。

```vue
<template>
  <el-button v-if="canAddElevator" type="primary" @click="openCreateDialog">
    新增电梯
  </el-button>
</template>

<script>
export default {
  name: 'SmartIOTElevatorControl',
  data() {
    return {
      canAddElevator: false
    }
  },
  created() {
    this.loadButtonAuth()
  },
  methods: {
    loadButtonAuth() {
      const resourceName = (this.$route && this.$route.name) || this.$options.name
      this.$api['button.info']({
        resourceName,
        parentUuid: '',
        permissionVo: { router: resourceName, resourceId: '' }
      }).then((buttons) => {
        this.canAddElevator = Array.isArray(buttons) && buttons.some((button) => {
          return button.name === 'elevatorControl_add' && button.enable !== '0' && button.isAccredit !== 0 && button.isAccredit !== '0'
        })
      }).catch(() => {
        // 接口失败时默认无权限，保持按钮隐藏。
        this.canAddElevator = false
      })
    },
    openCreateDialog() {
      if (!this.canAddElevator) return
      // 打开新增弹窗
    }
  }
}
</script>
```

对于新增、编辑、删除等高风险操作，除了模板中的 `v-if` 外，也应在对应方法开头再次判断权限，避免通过浏览器控制台或其他页面流程直接触发操作。

## 5. 全局 `v-auth` 指令

项目已提供全局 `v-auth` 指令，代码位于 `src/directives/modules/auth.js`。指令会按当前路由调用按钮权限接口，并按按钮的 `name` 或 `id` 判断；请求完成前和无权限时均隐藏元素。

基本用法：

```vue
<el-button v-auth="'elevatorControl_add'" type="primary">
  新增电梯
</el-button>
```

满足任意一个权限码即可显示：

```vue
<el-button v-auth="['elevatorControl_add', 'elevatorControl_edit']">
  维护电梯
</el-button>
```

同时具备全部权限码才显示：

```vue
<el-button v-auth.all="['elevatorControl_add', 'elevatorControl_edit']">
  高级维护
</el-button>
```

自定义资源名或传入权限上下文：

```vue
<el-button
  v-auth="{
    auth: 'elevatorControl_add',
    resourceName: 'SmartIOTElevatorControl',
    permissionVo: { router: 'SmartIOTElevatorControl', resourceId: '' }
  }"
>
  新增电梯
</el-button>
```

如果页面需要请求后处理多个权限、显示加载状态，或需要业务方法内二次校验，优先采用第 4 节的直接调用方式。

## 6. 标准 P8 表格页面

使用 `P8TableRender` 的标准列表页会将 `permissionVo` 传给平台组件。组件会调用按钮接口加载可见按钮，并结合 `/bpm/dmn/button/ButtonDecision/config` 返回的 `controlRule` 处理选中记录后的隐藏、置灰和提示。

```vue
<P8TableRender
  :code="componentsConfig.code"
  :permission-vo="componentsConfig.permissionVo"
/>
```

自定义 `<el-button>` 不会被标准表格组件自动接管，应使用本说明中的直接调用方式或 `v-auth` 指令。

## 7. 上线检查清单

1. 菜单资源已配置，并已授予目标角色。
2. 按钮资源的 `type` 为 `BUTTON`，`name` 使用稳定且唯一的权限码。
3. 按钮资源的 `enable` 已启用，且角色拥有该资源授权。
4. 页面使用的 `resourceName` 与后端资源查询所需的路由资源名一致。
5. 前端使用 `name`（不是 `title`）判断权限。
6. 无权限、接口异常和加载中状态均不展示敏感操作入口。
7. 后端业务接口已使用同一权限码完成鉴权与审计。
