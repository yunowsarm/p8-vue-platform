## 三、智慧安防

### 3.1 智能周界

1. 系统应在园区地图上展示围墙、围栏、出入口等防区及摄像机、雷达、红外对射等设备的在线、离线、故障和布撤防状态。
2. 系统应检测越界、攀爬、翻越、区域入侵和长时间徘徊等行为，并可分别设置生效区域、时段、目标类型、停留时间和灵敏度。
3. 告警发生后应自动保存位置、时间、目标抓拍和告警前后视频，并联动附近摄像机预置位、声光或语音设备以及安保移动端。
4. 系统应支持告警确认、误报标记、派单、现场处置、复核和关闭，任何告警不得无记录删除。
5. 系统应监测设备离线、遮挡、拆动和通信故障；对绿植、小动物、雨雪雾、逆光和施工临时撤防等场景，应给出降低误报的配置方案。

### 3.2 智能巡更

1. 系统应支持配置巡更路线、点位、班次、人员、时间窗口、检查内容和必拍照片等计划。
2. 系统应支持二维码、NFC、蓝牙或定位等签到方式，记录人员、时间、位置、设备和巡更结果，并防止代扫和事后补签。
3. 系统应对漏巡、迟巡、提前巡、越序巡和异常停留自动告警，并按规则升级至班组长或值班负责人。
4. 巡更人员应能上传文字、图片、语音和视频，发现问题后可直接生成安保或维修工单并跟踪闭环。
5. 地下室等无网区域应支持离线巡更，恢复网络后自动补传，并同时保留原始采集时间和补传时间。

### 3.3 消防预警

1. 系统应按确认范围接入消防报警主机、烟感、温感、电气火灾、消防水压液位等信息，统一展示火警、预警、故障、屏蔽和离线状态。
2. 消防事件应准确定位到建筑、楼层、防火分区和设备点位，平台显示内容应与消防专业系统原始信息一致。
3. 系统应按等级通知值班人员，联动附近视频、广播、门禁和电梯消防状态；实际控制动作必须服从消防专业系统和经审批的联动矩阵。
4. 火警不得被普通用户屏蔽、删除或远程复位；报警、确认、核查、联动、复位和关闭全过程均应留痕。
5. 系统应支持消防演练、设备测试、维修屏蔽和屏蔽超时提醒，并统计误报、故障、设备完好率和处置时长。
6. 本平台只承担信息集成、预警和辅助联动，不得替代法定消防报警及消防控制系统。

### 3.4 视频智能分析

1. 系统应监测摄像机离线、视频中断、画面冻结、画面遮挡、角度偏移和存储异常。
2. 系统应按实际点位配置人员入侵、徘徊、聚集、烟火、人员跌倒、遗留物、未佩戴防护用品、占用消防通道等算法，不接受只列算法名称而不落到点位。
3. 每个点位应能设置检测区域、排除区域、生效时段、目标持续时间、灵敏度和重复告警抑制时间。
4. 事件发生后应弹出实时视频和事件录像，保存抓拍、时间、位置和算法类型，并进入统一告警闭环。
5. 视频、图片的查看和导出应实行分级授权、审计和水印；涉及人脸等敏感信息时，应按最小必要原则采集和使用。
6. 每类算法应在对应真实点位、昼夜和典型天气条件下分别验收，不得以厂商实验室数据或“综合准确率”代替现场测试。

### 3.5 无线对讲

1. 系统应统一管理终端、人员、群组和频道，并显示终端在线、离线、电量和故障状态。
2. 系统应支持单呼、组呼、全呼、调度台呼叫和紧急呼叫；紧急呼叫应具有优先抢占能力。
3. 一键求助时应显示求助人员、终端编号和所在区域，并可联动附近摄像机和事件处置流程。
4. 系统应记录呼叫双方、开始与结束时间、类型和结果；如需录音，应明确授权、告知、查看权限和保存周期。
5. 地下室、电梯厅、设备间及室外重点区域应逐点开展覆盖和通话测试，并明确断网、干扰和低电量情况下的保障方式。

## 四、智慧通行

### 4.1 智慧停车

1. 系统应实时展示车位总数、空余数、占用情况、出入口通行和道闸、相机、诱导屏等设备状态。
2. 系统应监测占用消防通道、禁停区域、残障车位、充电车位、装卸区、跨车位、超时停车、逆行及堵塞出入口等违规情况，并可按区域和时段配置规则。
3. 违停事件应保存车牌、车辆及全景图片、位置、开始时间、持续时间和驶离时间，并支持语音提醒、通知巡查或转处置工单。
4. 系统应支持固定车、临时车、访客车、预约车、施工车、应急车和黑白名单管理，权限应包含有效期、可进入区域和特殊车位范围。
5. 系统应支持车牌识别、车位引导、停车计费、移动支付、发票、优惠减免、对账和退款等经甲方确认的业务，并明确与财务系统的对账口径。
6. 对无牌车、污损或相似车牌、摩托车、识别错误、网络中断和设备故障，应有人工处置及离线放行方案；人工改牌或抬杆必须记录人员和原因。
7. 应统计车流量、车位周转率、停车时长、违停次数、设备故障和异常抬杆；消防或紧急疏散时应支持经审批的道闸应急策略。

### 4.2 智能门禁

1. 系统应支持按人员、组织、门区、星期、时段和有效期配置通行权限，认证方式由甲方确定，可包括卡片、二维码、手机或生物识别。
2. 系统应监测非法认证、权限过期、连续失败、强行开门、门长时间未关、设备离线和防拆，并联动门口视频抓拍或录像。
3. 人员入职、调岗、离职、挂失和列入黑名单后，权限应按流程及时下发或回收，并显示下发成功、失败和离线待同步状态。
4. 远程开门、紧急开门、常开和权限批量调整应设置专门权限、二次确认及完整审计；重要区域宜采用审批或双人复核。
5. 断网时控制器应按本地合法权限继续运行并缓存记录，恢复网络后补传；断电和消防状态下的开门逻辑必须符合经审批的安全方案。

### 4.3 智能访客

1. 系统应支持访客预约、被访人审批、现场核验和登记，记录来访事由、被访人、访问区域、车辆和有效时间。
2. 系统应发放限定时间、区域和次数的二维码或临时凭证；预约取消、到期或访客离场后，凭证应自动失效。
3. 访客权限应与停车、门禁和梯控联动，只开放审批通过的车辆、门区和楼层。
4. 系统应对未审批到访、黑名单、证件异常、二维码重复使用、超范围通行和超时未离场进行提醒或告警。
5. 系统应支持团体访客、外协施工、送货人员和临时变更被访人的流程，并实时生成“当前在园访客清单”，供紧急疏散使用。
6. 访客数据应最小化采集、脱敏展示、限权导出，并按甲方确定的保存周期自动归档或删除。

### 4.4 智能梯控

1. 系统应按人员或访客、楼栋、电梯、楼层、时段和有效期配置乘梯权限，公共楼层和受限楼层应分开管理。
2. 门禁或访客身份核验通过后，访客只能在预约有效期内到达获批楼层；延期或取消应同步调整梯控权限。
3. 系统应监测无权限选层、凭证过期、异常连续认证、设备拆动、控制器离线及下发失败，并保留完整通行记录。
4. 系统应支持检修、消防和应急救援状态下的权限切换，并以电梯原系统安全逻辑为最高优先级。
5. 平台不得介入电梯安全回路，不得影响制动、门锁、检修和消防运行；断网时应有本地白名单及恢复补传机制。

## 五、能耗管理

> 本模块重点是“计量、统计、分析、考核和节能”，不负责替代设备保护或安全控制。

### 5.1 高低压配电能耗

1. 系统应按园区、楼栋、楼层、租户、功能区域、变压器和馈线建立分级计量，采集电量、电压、电流、功率、功率因数、需量和峰平谷数据。
2. 系统应展示用电流向、负荷曲线、最大需量、变压器负载率和峰平谷分布，并能逐级下钻到回路和表计。
3. 系统应分析变压器及线路损耗、三相不平衡、功率因数偏低、负荷突增突降、长期零值、计量倒退和表计离线等异常。
4. 系统应支持用电定额、费用预算和需量预测，按面积、人数、产值或运行时长进行单位能耗及同类对象对标。
5. 系统应生成日、月、季、年用电与费用报表，统计分项占比、异常用能和节能效果，并支持追溯原始数据。

### 5.2 照明能耗

1. 系统应按楼栋、楼层、公共区域、室外区域、配电箱和照明回路采集电量、开关、调光及运行时长数据。
2. 系统应计算单位面积和单位运行小时能耗，监测非使用时段亮灯、无人区域长亮、能耗突增及状态与电量不一致。
3. 系统应结合工作日、节假日、日出日落、人员存在和光照度分析照明策略执行情况及可节能时段。
4. 系统应比较分区、定时、调光和人感等策略实施前后的节电量、节电率和费用变化。
5. 消防应急照明不得纳入普通节能控制，人工现场控制应具有最高或经审批的优先级。

### 5.3 电梯能耗

1. 系统应按单梯或梯组采集累计电量、实时功率、运行用电和待机用电，并关联运行次数、时长和时段。
2. 系统应计算单次运行、单位运行小时和待机能耗，对同型号、同用途电梯开展横向对标。
3. 系统应发现待机功率异常、长期高负荷、功率突变、计量中断及运行状态与功率不一致等情况。
4. 系统应分析高峰、低客流和夜间运行效率，形成休眠、错峰或群控优化建议，并量化策略实施效果。
5. 节能策略只能经甲方批准后由电梯原厂群控系统执行，不得直接修改电梯安全控制逻辑。

### 5.4 给排水能耗

1. 系统应按园区入口、楼栋、楼层、租户和主要用途建立分级水计量，并同步采集主要水泵用电。
2. 系统应展示瞬时流量、累计用水、分区占比和水量平衡，计算未计量水量或差额。
3. 系统应识别夜间最小流量异常、持续小流量、流量突增、水表倒流、计量离线和长时间补水等疑似跑冒滴漏。
4. 系统应计算泵组每立方米输水电耗，对不同泵组和时段进行效率比较，并支持用水定额与预算预警。
5. 严重泄漏应自动推送至设备管理模块形成工单；关阀动作必须人工确认并不得影响消防、应急或重要生产用水。
