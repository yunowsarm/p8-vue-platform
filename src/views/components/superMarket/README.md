# 超市物联

- 路由与菜单由后台配置生成，不在 `constantRouterMap` 中注册。
- 统一入口文件：`superMarket.vue`，后台菜单组件路径：`components/superMarket/superMarket`。
- 入口组件保留在模块外层；`SalesDataView.vue`、`SalesAnalysis.vue`、`SalesMetrics.vue`、`SalesTrend.vue` 统一放在 `components/`，接口、字段和图标由模块统一维护。
- 数据视图和数据分析均由该入口通过页内图标切换，后台只配置一个菜单组件；实际访问地址以后台路由配置为准，沿用平台登录校验。
- 页面布局参考 `electricitySummary/index.vue`：顶部查询栏右侧图标切换视图，`keep-alive` 保留子视图；数据视图为趋势、设备汇总和明细面板，分析视图为指标卡、结论与图表。
- `fields.js` 维护表字段、接口字段和业务类型码值；无需后端提供中文列名。
- `fields.js` 的 `DEVICE_NAMES` 统一维护设备显示名称：`POS_TEST_001` 映射为“津通大门超市”，详情、图表及导出使用该名称；筛选值、分组键和交易去重仍保留原始设备 ID，未配置的设备显示原 ID。
- 销售详情隐藏记录 ID、商品标识、设备名称及接收时间；详情和明细表中的交易时间统一使用 `o00781`。
- 数据视图导出 Excel 明细；分析视图的“导出报告”可选择 HTML 或 PDF：HTML 直接下载独立报告，PDF 打开报告打印窗口并在图表加载完成后调起打印，选择“另存为 PDF”。两种格式包含相同的筛选范围、指标、分析概览、图表、商品排行、业务类型和每日金额统计。分析页不再展示设备贡献图。
- 请求定义位于 `src/service/api/modules/superMarket.js`，通过统一的 `$api['superMarket.salesDetails']` 调用 GET `/api/pos/sales-details/query`，沿用平台环境地址、登录凭证和响应拦截器。`src/service/superMarket.js` 负责完整分页加载及数据完整性检查。

## 数据口径

日期默认当天，支持昨天、近七天和任意时间范围。先加载全部分页，再在前端筛选、分页、汇总和导出，最多 10,000 条。超过限制、查询期间总数变化、分页重复或缺失时展示错误，不展示部分汇总。并发查询仅应用最新结果。接口未提供快照能力，相同总数下的实时变更不能完全检测。

金额以 `b00517` 原值累计；`b01058` 的 A / B 分别表示销售 / 退货，不推测退货金额的正负规则，不计算净额。数量仅逐行显示，不跨不同商品单位相加。单数按设备编号加单号去重。缺少有效金额的记录不计入金额汇总。

数据视图、分析页及导出报告共用 `analysis.js` 中的趋势统计，以 `o00781` 交易日期汇总全部筛选明细，与表格交易时间口径保持一致，不随表格分页改变。缺少有效交易日期或金额的记录不进入趋势，也不回退到 `receivedAt` 接收日期；接收时间可能晚于实际交易时间。商品排行按 `o01292` 分组，缺失时以商品名称兜底；不将 `o01292` 直接解释为条码。

商品分类、支付方式、库存尚无查询接口，当前只保存已确认的映射，不生成对应数据。`o00781` 已确认为交易时间；销售接口 `b00495` 的成本含义尚待确认，不计算毛利。

## 验证

`node --test tests/superMarket-trend.test.cjs` 覆盖延迟上报跨日、图表与表格同口径、无效日期与金额、导出报告每日统计。

运行 `node --test tests/superMarket.test.cjs` 验证统计、分页完整性、旧请求失效、模板编译和测试文件隔离。

Node 测试必须放在项目根目录 `tests` 中。项目存在 `import('@/views/' + comp)` 动态加载，将 Node 测试放在 `src/views` 中会使生产构建尝试打包 `node:fs` 等内置模块并失败。
