# 线索数据分析

入口：原 `admin.vue` 顶部的「数据分析」；独立页面组件为 `components/intentionInquiry/analysis`，可按现有动态菜单机制配置。复用平台 `$api['reception.list']` 和当前登录态，不需要增加后端接口或配置新凭证。

数据源：`GET /jt/reception/list`，参数 `viewType=0, pageNo, pageSize=200`。顺序读取全部分页并按线索 ID 去重；出现缺页、重复分页或错误返回时终止统计并提示，不展示部分数据或示例数据。一次最多查询 1000 页，超出后提示改用服务端统计。页面每分钟更新逾期判断时间，刷新按钮重新读取业务数据。

## 已实现

- 线索创建日期、渠道、当前负责人联合筛选。
- 线索总数、当前签约占比、A/B 级待推进数、跟进逾期数。
- 最近 12 个月新增趋势（以日期筛选结束月为终点，默认本月）、当前阶段分布、渠道获客与签约量、客户等级、行业、需求面积和意向空间分布。
- 当前负责人负荷、签约占比、跟进覆盖率、累计跟进次数、逾期数量。
- 全部、逾期、待分配、未跟进、高意向、无效线索明细，企业搜索、全量排序和分页。
- 空数据、接口错误、加载进度和缺失数据说明。

## 口径

跟进子表为 `records`。最新状态与管理页保持一致，按 `createdAt || followUpTime` 排序，不单纯按可补录的跟进日期排序。没有跟进记录的客户等级为「未记录」，不会擅自计入 E 级。

`approveStatus/approve_status=2` 为无效线索；当前签约数排除无效线索。签约占比的分母为全部筛选后线索。待推进排除无效、当前已签约和 F 级；逾期仅判断最新记录中明确填写的 `nextFollowUpTime`，不推断工作日或节假日。阶段图表示当前分布，不宣称历史阶段转化率。负责人汇总按照当前归属展示，历史跟进次数不能解释为该负责人本人完成的次数。

行业、面积、意向空间按原页面枚举解释。面积区间不能相加为总面积。成本、合同金额、收入数据不在已知接口中，因此不计算 ROI、获客成本或收入预测。

## 验证

`node tests/intention-inquiry-analysis.cjs`

Node 测试保存在项目根目录的 `tests/`，不能放入 `src/views/`：平台部分动态组件会扫描整个 views 目录，导致 Node 内置模块被错误纳入浏览器构建。

已通过 ESLint、Vue 模板/脚本与 SCSS 编译检查、数据口径及分页测试，并在现有本地平台的有效登录会话中完成真实数据加载、渠道筛选及逾期明细下钻验证。入口为 `/#/intention_inquiry` →「数据分析」。验证时共读取 13 条线索（有效 11、无效 2、当前签约 1），这些是会变化的业务快照，不在代码中写死。生产页面没有内置演示数据。
